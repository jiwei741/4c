# 南京季度版训练接入方案

本文档对应当前成员 AA 的算法与模型训练工作。

目标是把以下两部分接进当前训练框架：

- 南京 `309` 网格季度版遥感特征  
  来源：[remote_sensing_output_ver.03.20](../remote_sensing_output_ver.03.20)
- `computer_design` 仓库 `master` 分支中的 `ERA5 + GPP` 提取思路  
  来源：external/computer_design (`external/computer_design`)

## 一、当前结论

### 1. 哪些已经能用

- grid_nodes.csv (`remote_sensing_output_ver.03.20/remote_sensing_output_ver.03.20/grid_nodes.csv`)
- nanjing_sentinel2_features_quarterly_2020_2024.csv (`remote_sensing_output_ver.03.20/remote_sensing_output_ver.03.20/nanjing_sentinel2_features_quarterly_2020_2024.csv`)

这两份数据已经被清洗并迁移到正式目录：

- [data/processed/features/nanjing/quarterly/grid_nodes.csv](../data/processed/features/nanjing/quarterly/grid_nodes.csv)
- [data/processed/features/nanjing/quarterly/sentinel2_features.csv](../data/processed/features/nanjing/quarterly/sentinel2_features.csv)

这意味着：

- 南京季度版 `Sentinel-2` 输入已经能接进训练链路
- 当前共有 `309` 个节点、`20` 个季度时间步

### 2. 哪些还没法直接用

`computer_design` 的 `master` 分支只能复用“逻辑”，不能直接复用“数据”。

原因：

- 它的 data_stream-moda.csv (`external/computer_design/data_stream-moda.csv`) 只有江宁区 `15` 个点位
- 实测映射到南京 `309` 网格时，最近点距离超过 `50km`
- 这说明它不够覆盖整个南京研究区

结论：

- `ERA5.py` 可复用变量选择思路
- `GPP.py` 可复用栅格转标签思路
- `data_stream-moda.csv` 不能直接作为南京训练特征

## 二、已迁移的脚本

当前已经新增并可用：

- [nanjing_quarterly_dataset.yaml](../services/inference/configs/nanjing_quarterly_dataset.yaml)

## 三、接入步骤

在 [services/inference](../services/inference) 目录下执行：

```bash
uv sync
uv run --offline python prepare_nanjing_quarterly_remote_sensing.py
uv run --offline python build_nanjing_era5_quarterly_features.py --era5-csv <monthly_era5.csv>
uv run --offline python extract_nanjing_gpp_quarterly_labels.py --tif-dir <monthly_gpp_tif_dir>
uv run --offline python build_training_dataset.py --config configs/nanjing_quarterly_dataset.yaml
uv run --offline python train.py --config configs/lstm_baseline_quarterly.yaml --dataset ../../data/processed/inference/nanjing_quarterly_v1.npz
uv run --offline python train.py --config configs/stgnn_gcn_lstm_quarterly.yaml --dataset ../../data/processed/inference/nanjing_quarterly_v1.npz
```

## 四、现在还缺什么

目前真正缺的不是模型代码，而是两份输入：

1. `ERA5` 月度点位表  
要求至少包含：
- `valid_time`
- `latitude`
- `longitude`
- `t2m`
- `tp`
- `u10`
- `v10`

2. `GPP` 月度 GeoTIFF 目录  
要求文件名里能解析出 `YYYYMM`

这两项到位后，就能直接拼季度训练集。

## 五、本电脑是否可训练

当前机器资源：

- GPU：`RTX 3050 Laptop GPU 4GB`
- RAM：`16GB`
- 可用磁盘：约 `61GB`

### 可以训练的范围

对于当前这套季度版数据，本机可以训练：

- `309` 节点
- `20` 个季度时间步
- `4` 个季度输入窗口
- `1` 个季度预测
- `LSTM baseline`
- 当前版 `GraphConv + LSTM`

### 不适合在本机做的内容

- `SAM-2` 批量遥感推理
- 全量 Sentinel-2 原始影像处理
- 大规模月度 ST-GNN 长时间调参
- 更复杂的 PyG 大模型实验

### 实际建议

- 本机：负责季度版样本拼接、训练代码开发、小规模实验
- 服务器 / AutoDL：负责正式训练、批量调参、月度完整版实验

## 六、一句话结论

当前南京季度版遥感数据已经能作为训练输入的一部分。  
`computer_design` 的 `master` 分支思路已经迁移为本项目可用脚本，但它自带的江宁 `15` 点数据不能直接拿来训练南京 `309` 网格模型。  
本电脑能训“季度版小模型”，不能训“原方案完整版大模型”。
