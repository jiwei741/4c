# 平台联调与启动说明

更新时间：`2026-03-22`

## 当前可本地运行的部分

- `services/backend`
  - 聚合模型结果
  - 提供预测、情景推演、管理、数据源切换接口
- `services/frontend`
  - 平台业务工作台
  - Cesium 地图骨架
  - 预测 / 热点 / 模型差异 / 情景增量视图
- `services/inference`
  - 已训练好的季度版模型
  - 真实情景推演脚本
- `services/data_ingestion`
  - Sentinel-2 / ERA5 下载入口封装
- `services/segmentation`
  - 远程 `SAM-2` bundle、manifest、结果回收链路

## 当前不在本机执行的部分

- 真实 `SAM-2` 批量推理
- 大规模 `Sentinel-2` 原始影像分割

原因：本机显存不足以稳定承担原方案里的 `SAM-2` 遥感批处理。  
本地只负责准备任务、导出 bundle、导入服务器结果。

## 环境约束

- 启动方式统一使用 `uv`
- 不依赖主环境 Python
- `backend` 和 `frontend` 会各自使用自己的 `.venv`

## 启动前提

1. 已安装 `uv`
2. `.env` (`.env`) 已填写项目需要的凭证和配置
3. 本机端口未被占用
   - `8000`：backend
   - `4173`：frontend

## 一键启动

```powershell
cd d:\4c
powershell -ExecutionPolicy Bypass -File scripts/start_platform.ps1
```

启动成功后会自动打开浏览器；如需跳过：

```powershell
cd d:\4c
powershell -ExecutionPolicy Bypass -File scripts/start_platform.ps1 -NoBrowser
```

如果你想强制重建 `uv` 环境：

```powershell
cd d:\4c
powershell -ExecutionPolicy Bypass -File scripts/start_platform.ps1 -ForceSync
```

启动成功后会输出：

- `Backend PID`
- `Frontend PID`
- `Mode: uv`
- `PID file: d:\4c\logs\platform\platform.pids.json`
- `Frontend URL`
- `Backend Health URL`

## 常见问题

### 1. 端口被占用

如果 `8000` 或 `4173` 已被其他进程占用，启动会失败。  
先停止已有服务，再重新执行启动脚本。

### 2. `uv sync` 失败

先确认：

- `uv` 已正确安装
- 当前网络可访问依赖源
- 目录有写权限

然后重新执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start_platform.ps1 -ForceSync
```

### 3. `SAM-2` 没有真实结果

这是当前预期行为。  
如果服务器端结果还没回传，平台会自动使用 `quarterly_proxy` 遥感特征继续运行；等 `SAM-2` 结果导回本地后，系统会按配置自动切换或允许手动切换。
