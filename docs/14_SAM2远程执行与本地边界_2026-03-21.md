# SAM-2远程执行与本地边界

## 结论

`SAM-2` 真实批量推理不放在当前本机执行。

原因：

- 当前机器是 `RTX 3050 Laptop GPU 4GB`
- 原方案对 `SAM-2 推理 + ST-GNN 训练` 建议 `16GB+` 显存
- 本机继续承担平台开发和季度版模型已经合适，但不适合历史 Sentinel-2 批量分割

所以当前工程边界固定为：

- 本地负责：数据检索、任务清单、平台开发、模型训练、前后端联调、结果接收
- 服务器负责：真实 `SAM-2` 推理和批量分割

## 本地继续做什么

这些内容都继续在本地完成：

1. `services/data_ingestion`
2. `services/backend`
3. `services/frontend`
4. `services/inference`
5. `services/segmentation` 的任务清单和远程交付骨架

也就是说，本地不停止推进平台，只把最吃显存的 `SAM-2` 推理迁走。

## 服务器需要承担什么

服务器只负责这一段：

1. 接收已下载好的 `Sentinel-2 SAFE`
2. 读取 `sam2_job_manifest.json`
3. 执行真实 `SAM-2` 分割
4. 输出每景的 `mask` 和场景级特征
5. 回传合并后的 `sentinel2_features_from_sam2.csv`

## 推荐服务器配置

最低建议：

- GPU 显存 `8GB`
- RAM `32GB`
- 磁盘可用空间 `100GB+`

更现实的可用配置：

- GPU 显存 `12GB-16GB+`
- RAM `32GB-64GB`
- 磁盘 `200GB+`

如果要按原方案继续往“批量历史影像 + 流式更新”走，直接按 `16GB+` 显存准备更稳。

## 当前已经补好的迁移脚本

### 本地导出 bundle

- [export_remote_sam2_bundle.py](../services/segmentation/export_remote_sam2_bundle.py)

作用：

- 从 Sentinel-2 下载计划生成远程执行 bundle
- 固定服务器目录约定
- 产出 `TRANSFER_CHECKLIST.md`

命令：

```powershell
cd d:\4c\services\segmentation
python export_remote_sam2_bundle.py --plan-json d:\4c\data\raw\sentinel2\nanjing\catalog\sentinel2_download_plan_nanjing_2025-01-01_to_2025-01-31.json
```

输出目录默认是：

- `d:\4c\data\processed\segmentation\nanjing\remote_bundle\sam2_remote_bundle_<timestamp>\`

### 服务器准备 workspace

- [prepare_remote_sam2_workspace.py](../services/segmentation/prepare_remote_sam2_workspace.py)

作用：

- 在服务器上按 manifest 创建输出目录
- 检查 Sentinel-2 SAFE 是否已经镜像到位
- 生成 `server_job_plan.json`

命令示例：

```bash
cd /workspace/spatio-eco/services/segmentation
python prepare_remote_sam2_workspace.py \
  --manifest /workspace/spatio-eco/data/processed/segmentation/nanjing/remote_bundle/<bundle>/sam2_job_manifest.json \
  --server-workdir /workspace/spatio-eco
```

### 本地回收结果

- [import_remote_segmentation_results.py](../services/segmentation/import_remote_segmentation_results.py)

作用：

- 校验服务器回传目录
- 汇总缺失场景
- 将合并后的特征 CSV 复制回本地训练路径

命令示例：

```powershell
cd d:\4c\services\segmentation
python import_remote_segmentation_results.py ^
  --manifest d:\4c\data\processed\segmentation\nanjing\remote_bundle\<bundle>\sam2_job_manifest.json ^
  --results-root d:\4c\data\processed\segmentation\nanjing
```

默认导入目标是：

- `d:\4c\data\processed\features\nanjing\quarterly\sentinel2_features_from_sam2.csv`

## 服务器目录约定

统一按 repo 根目录为 `/workspace/spatio-eco` 约定。

### 输入

- `data/raw/sentinel2/downloads/<scene_id>/`

### 输出

- `data/processed/segmentation/nanjing/<scene_id>/masks/`
- `data/processed/segmentation/nanjing/<scene_id>/features/`

### 合并特征

- `data/processed/features/nanjing/quarterly/sentinel2_features_from_sam2.csv`

## 现在本地还能继续做什么

在服务器 SAM-2 还没接入之前，本地不需要等待，可以继续：

1. 完善 `backend` 接口
2. 完善 `frontend` Cesium 页面
3. 继续平台联调
4. 继续情景推演和结果展示
5. 继续维护 `data_ingestion`

也就是说，当前项目可以进入“双线推进”：

- 本地线：平台和联调
- 服务器线：后续补真实 `SAM-2`

## 当前限制

当前仓库仍然**没有真实 SAM-2 推理实现**，只是把迁移边界和执行骨架固定好了。

所以后续上服务器时，你们还需要再补一段：

- 真实 `SAM-2` 模型加载
- 遥感切片读取
- mask 输出
- 场景级特征汇总

但这一步已经和本地平台解耦，不会再阻塞现在的开发。
