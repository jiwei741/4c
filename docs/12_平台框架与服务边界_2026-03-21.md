# 平台框架与服务边界
更新时间：`2026-03-29`

## 当前目标

当前平台目标已经收敛为一条可本地联调、可重复训练的季度版南京链路：
1. 使用 `309` 个网格节点和 `2020-Q1` 到 `2024-Q4` 的季度数据完成训练、预测与展示
2. 使用高精度季度 Sentinel-2 地类特征作为当前正式遥感输入
3. 保留数据接入与流式处理骨架，当前运行链路只保留必要模块

## 平台分层

### 1. 数据接入层
- 目录：`services/data_ingestion`
- 责任：Sentinel-2、ERA5、EDGAR、GPP 等原始数据接入
- 状态：骨架已在，真实下载与编排仍待继续补充

### 2. 遥感特征层
- 目录：`services/inference`
- 责任：季度 Sentinel-2 特征标准化、训练输入拼接
- 当前来源：`data_for_memberA` 的高精度季度包
- 当前输出：
  - `data/processed/features/nanjing/quarterly/grid_nodes.csv`
  - `data/processed/features/nanjing/quarterly/sentinel2_features.csv`

### 3. 推理训练层
- 目录：`services/inference`
- 责任：训练集构建、模型训练、预测、情景推演
- 当前默认模型：
  - 单步：`stgnn_single_step_hybrid`
  - 多步：`stgnn_multistep_hybrid`

### 4. 后端 API 层
- 目录：`services/backend`
- 责任：聚合模型产物、输出平台数据接口、执行情景推演
- 当前说明：
  - 直接读取文件产物
  - 仅保留当前平台需要的接口集合

### 5. 前端展示层
- 目录：`services/frontend`
- 责任：Cesium 地图、预测图层、细节面板、情景推演入口
- 状态：Vue 3 + Vite 单页应用

### 6. 流式与数据库层
- 目录：`services/streaming`、`infra`
- 责任：Kafka / Flink / PostGIS 边界预留
- 状态：仍为骨架

## 成员分工

| 成员 | 模块 | 当前目录 | 状态 |
|---|---|---|---|
| 成员 A | 训练、预测、情景推演 | `services/inference` | 已接入 refined quarterly 数据并完成重训 |
| 成员 B | 遥感与地类特征 | `services/data_ingestion` + `data_for_memberA` | 当前以高精度季度包支撑平台 |
| 成员 C | 流式处理与数据库 | `services/streaming` + `infra` | 骨架保留 |
| 成员 D | 后端 API | `services/backend` | 当前平台接口可运行 |
| 成员 E | 前端展示 | `services/frontend` | 当前单页平台可运行 |

## 当前默认交付路径

1. 以高精度季度 Sentinel-2 特征生成正式训练输入
2. 由 `services/inference` 输出模型权重、指标、预测与情景结果
3. 由 `services/backend` 聚合这些产物供前端调用
4. 由 `services/frontend` 提供地图和业务演示页面

## 当前展示基线

- 研究区：南京市
- 网格规模：`309`
- 时间粒度：季度
- 时间范围：`2020-Q1` 至 `2024-Q4`
- 当前 Sentinel-2 来源：`local_highres_quarterly`
