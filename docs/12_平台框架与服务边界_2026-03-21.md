## 当前平台目标

先完成一个可联调的季度版南京 MVP：

1. 用南京 `309` 个网格节点和 `2020-Q1` 到 `2024-Q4` 的季度数据打通整个平台。
2. 平台先接成员 A 已经完成的模型输出，再逐步替换为成员 B、C、D、E 的真实在线流程。
3. 先保证“全链路可演示”，再逐步把批处理替换成真流式、把静态可视化替换成 Cesium 三维地球。

## 平台分层

### 1. 数据接入层

- 服务目录：`services/data_ingestion`
- 责任人：成员 B + 大数据工程师
- 数据源：
  - Sentinel-2
  - ERA5
  - EDGAR
  - NOAA
  - GPP / MODIS
- 当前状态：
  - 原始下载脚本已分散存在于 [scripts](../scripts) 和 [services/inference](../services/inference)
  - 统一的服务骨架这次开始补

### 2. 遥感分割层

- 服务目录：`services/segmentation`
- 责任人：成员 B
- 目标：
  - Sentinel-2 L2A 影像预处理
  - SAM-2 批量分割
  - ESA CCI / WorldCover 联合标注
  - 输出地类面积和网格特征
- 当前状态：
  - 输入数据和特征需求明确
  - 真正的 SAM-2 服务尚未接入平台

### 3. 流式计算层

- 服务目录：`services/streaming`
- 责任人：成员 C
- 目标：
  - Kafka 负责切片任务和特征更新消息
  - Flink 负责历史回放和准实时特征更新
  - PostGIS 负责时空结果落库
- 当前状态：
  - 平台先按“批处理优先、流式接口预留”的策略搭建
  - 真正的 Kafka/Flink 作业后补

### 4. 智能推演层

- 服务目录：`services/inference`
- 责任人：成员 A
- 当前已完成：
  - 季度版训练数据拼接
  - `LSTM baseline`
  - `ST-GNN + EDGAR + feature norm + hybrid_wind_knn`
  - 多步预测
  - 情景推演增强
- 当前默认模型：
  - 单步：`stgnn_single_step_hybrid`
  - 多步：`stgnn_multistep_hybrid`

### 5. 后端 API 层

- 服务目录：`services/backend`
- 责任人：成员 D
- 目标：
  - 暴露健康检查、模型清单、预测结果、情景推演接口
  - 聚合 PostGIS、模型输出、场景结果
- 当前状态：
  - 这次先补第一版 API 骨架
  - 先读取成员 A 的真实输出文件，不直接跑在线训练

### 6. 前端可视化层

- 服务目录：`services/frontend`
- 责任人：成员 E
- 目标：
  - 研究区总览
  - 预测结果展示
  - 情景推演面板
  - 后续替换成 Cesium.js + Vue 3
- 当前状态：
  - 这次先补静态可运行原型
  - 后续再接三维地球和时间轴

## 当前默认交付路径

### 第一阶段

- 用 [services/inference](../services/inference) 的季度版模型成果，先把 API 和前端展示跑通。
- 后端直接读取现有：
  - `metrics.json`
  - `latest_prediction.json`
  - `enhanced_scenario.json`

### 第二阶段

- 成员 B 接入真实网格特征产出
- 成员 C 接入 Kafka/Flink 的历史回放链路
- 成员 D 把静态文件读取替换成数据库和在线推理
- 成员 E 把静态页面替换成 Cesium.js 三维平台

## 推荐填充顺序

1. 先用后端读成员 A 现有输出，前端把指标和情景结果展示出来。
2. 再补数据接入和分割服务的输入输出约定。
3. 再接真实 PostGIS。
4. 最后再上 Kafka/Flink 和 Cesium。

## 说明

这次补的是“平台骨架”，不是全量系统终态。骨架的意义是：

- 先让成员 A 到成员 E 的目录和接口边界固定下来
- 让现有模型成果可以直接进入平台展示
- 让后续成员填代码时不再改目录结构
