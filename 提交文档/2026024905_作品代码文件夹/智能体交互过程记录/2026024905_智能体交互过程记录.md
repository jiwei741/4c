# 智能体交互过程记录（整理摘录）

作品开发过程中引入了以 Codex 为代表的智能体协作方式，但始终坚持“人工主导决策、智能体辅助执行”的原则。智能体主要承担两类任务：一是代码与配置检视，例如定位前端地图显示异常、情景推演二次框选失效、Docker 生产构建兼容性等问题，并在不破坏平台接口的前提下给出修复方案；二是实验自动化支持，例如补齐 multi-seed 与 adjacency sweep 脚本，对比正式模型与候选模型的指标表现。所有关键修改均经过本地构建、接口回归和页面检查后才被保留，因此智能体在本作品中的角色更接近“工程增效器”，而不是脱离项目事实的自动生成工具。

从使用效果看，智能体最大的价值不在于替代建模判断，而在于缩短工程闭环的调试时间。尤其在前后端联调、文档与部署材料整理、实验结果复核等高重复度工作中，智能体能够快速完成搜索、比对和脚本化实现，使团队把更多精力放在问题抽象、指标判断和结果解释上。这种协同方式与作品本身强调的“数据—模型—服务”闭环是一致的，也为后续作品维护提供了更高的可追溯性。

## 记录说明

本记录采用“关键协作任务整理摘录”的方式，聚焦智能体在需求理解、方法建议、代码修改、结果复核和部署材料整理中的具体贡献，不包含全部对话原文。

## 智能体承担的主要任务

1. 前后端问题定位与修复：包括首页结构重构、地图层显示异常排查、情景推演二次框选失效修复、对比视图交互优化、FAQ 助手与平台使用引导接入等。
2. 实验自动化与结果核对：补齐 multi-seed 与 adjacency sweep 脚本，对正式模型与候选模型做指标对比，并保持平台接口不被实验脚本破坏。
3. 交付与部署材料整理：生成 Docker 发布版、Release 包、提交目录结构与部署说明，协助完成可交付材料收口。

## 真实性说明

所有关键代码和配置修改均由团队成员审阅与决定，智能体给出的建议只有在通过本地构建、接口联调、页面检查和结果验证后才会被保留。智能体在本作品中的定位是“工程协作工具”，不替代团队对研究问题、指标解释和最终方案取舍的人工判断。
